# A Personal Operating System for Clarity and Decisions

I don’t use tools to remember more.  
I use them to **decide better**.

This is the manifesto behind my personal operating system — a way of working designed to reduce noise, sharpen thinking, and create progress without drowning in tasks or information.

---

## 1. I don’t outsource my thinking

AI can summarise, connect, and propose.  
It can accelerate processing.

But understanding is not something I outsource.

If I don’t invest time in finding patterns and forming my own mental model, I don’t build knowledge. I only move faster in the short run without getting better in the long run.

AI accelerates processing.  
Sensemaking remains my responsibility.

---

## 2. I separate knowledge from execution

Knowledge and tasks serve different purposes.

- **Knowledge** exists to improve judgment and decision quality.
- **Tasks** exist to enable execution.

When these get mixed, I lose clarity:
- tasks start to feel like progress
- knowledge turns into clutter

Tasks are temporary.  
Knowledge must be reusable.

---

## 3. I optimise for decisions, not memory

My system is not built to remember everything.

It is built to:
- surface the right questions
- make uncertainty explicit
- force decisions instead of drift

Anything that does not help me decide — directly or indirectly — is secondary.

---

## 4. Capture is cheap, sensemaking is not

Everything starts with capture:
- raw
- fast
- unstructured
- without judgment

Capture is intentionally dumb.

Sensemaking happens later, through distillation:
- reducing input
- connecting ideas
- extracting implications

I don’t accumulate notes.  
I distil understanding.

---

## 5. Archiving is a sign of maturity, not loss

Not all knowledge should stay active forever.

When information no longer improves my thinking or decisions, I archive it:
- not to forget it
- but to remove it from my active attention

Archiving is not deletion.  
It is deactivation.

Attention is finite. My system respects that.

---

## 6. Projects exist to resolve uncertainty

An active project is not a list of tasks.

> **An active project is a deliberate effort with a clear target condition and at least one open core decision.**

Projects exist to reduce uncertainty through explicit choices.

A project is done when the relevant decisions are made — not when every task is executed.

---

## 7. I use few tools, each with a single purpose

I intentionally keep my toolset small:

- **Obsidian** to think, structure, and document
- **AI (Claude Code / Codex)** to interact with my knowledge and accelerate processing
- **Todoist** to manage concrete next actions

Each tool has a clear role.  
No tool tries to do everything.

---

## 8. Principles over productivity hacks

I work by a small set of non-negotiable principles:

- Capture is always raw and unstructured  
- Sensemaking happens through distillation, not accumulation  
- Decisions are explicit moments, not implicit drift  
- Tasks exist only to enable decisions or execution  

If speed conflicts with clarity, I choose clarity.

---

## Closing

This operating system is not about doing more.

It is about:
- reducing mental noise
- creating space for thinking
- and making better decisions, consistently

Progress without clarity is just motion.

I choose clarity.
